## 自分が作ったワールドについて
VRChat で［WIP］ペラゴス諸島（Pelagos Islands）というワールドを作っています。潜水艦から戦闘機で出撃して戦う、空戦のワールドです。

自分はこのワールドに、インスタンスをまたいで、最高点を競う世界ランキングを作りました。このランキングを作るうえで、VRCでは、「インスタンスが閉じた時情報が消えてしまう」や「いないプレイヤーの情報を表示することはできない（プレイヤーごとにそのワールドでの点数は保存できるが、そのプレイヤーが退出するとデータを保持できない）」という点を解決する必要がありました。そのため自分は外部のサーバーにデータを送って保存するという仕組みでこのランキングを実装しました。


この記事では、自分がどのようにこのようなランキングを実装したのかを説明したいと思います。

## 世界ランキングについて

まず、自分の制作したワールドの世界ランキングについて詳しく説明します。

- ランキングに参加するかどうかは **自分で選べます**（スイッチを入れた人だけが送ります）。最初はオフです。
- 送るのは **最高点** と **選んだ称号の番号** だけです。**名前（VRChat の表示名）は送りません。**
- **IP アドレスは保存しません。** 「同じ人の記録を 1 つにまとめる」ために、IP アドレスを元に戻せない形（塩付きハッシュ）に変えて使います。
- 表示されるのは **点数・日付・国・称号** だけです。

# 全体の構成

```
 VRChat（ワールド）                         サーバー（Cloudflare Workers）           GitHub Gist
 ───────────────                        ──────────────────────           ─────────
  最高点が上がった ── /s/<点数> ───────→  記録を受け取る                   
  称号を選んだ     ── /b/<番号> ───────→  （上位 50 件だけ覚える）  ── 上位 5 件 ──→ scores.json
                                                                               │
  ランキングを表示 ←────────────────────── 読む ────────────────────────────┘
```

- ワールドから送るのは、`https://〜/s/123` のような **URL を 1 回開くだけ** です（VRChat の `VRCStringDownloader`）。URL に入っているのは点数（または称号の番号）だけです。
- ワールドがランキングを読むのは、サーバーではなく **GitHub Gist** です。Gist には上位 5 件の「点数・日付・国・称号」だけを書き出しています。
- VRChat では、決められた場所（GitHub など）以外の URL は、設定の **「Allow Untrusted URLs」** をオンにしている人しか開けません。そのため、**記録を送れるのはこの設定をオンにしている人だけ** です（ランキングを見るのは誰でもできます）。

# そもそも IP アドレスとは

IP アドレスは、インターネットにつながっている機械に割り当てられる **「住所」のような番号** です（例: `203.0.113.45`）。Web サイトを見たり、VRChat で遊んだりするとき、相手のサーバーは「どこへ返事を送ればいいか」を知るために、この番号を必ず受け取ります。つまり、**どんなサーバーでも、通信が届いた時点で IP アドレスは見えています。**

ただし、IP アドレスから分かるのは、だいたい次のようなことだけです。

- どの国・どの地域から、どのプロバイダ（回線の会社）を使ってつないでいるか
- 名前や住所、VRChat のアカウントなどは、IP アドレスからは分かりません

それでも、IP アドレスを長く保存したり、ほかの情報と組み合わせたりすると、「同じ人がいつ何をしたか」を追いかける手がかりになります。なので、このランキングでは **IP アドレスを保存せず、必要な所だけ元に戻せない形にして使う** ことにしました。

# なぜ IP アドレスを使うのか

ランキングを作るとき、困ることが 2 つありました。

1. **同じ人の記録がずらっと並んでしまう**
   名前を送らないので、サーバーには「誰の点数か」が分かりません。何も工夫しないと、1 人が 100 点、120 点、150 点…と記録を伸ばすたびに、全部が別の行として並んでしまいます。
2. **荒らし対策ができない**
   URL を何度も開けば、ランキングをいたずらで埋めることができてしまいます。

この 2 つを解決するために、「**送ってきたのが同じ接続元かどうか**」だけを見分けたい。ここで接続元の IP アドレスを使います。ただし、**IP アドレスそのものは保存しません。**

# IP アドレスを保存しない仕組み：塩付きハッシュ

サーバーでは、受け取った IP アドレスを次のように変換してから使います。

```js
// サーバーの中だけにある、ランダムな文字列（塩）。最初に 1 回だけ作って、サーバーの中に保存する
let salt = await s.get("salt");
if (!salt) { salt = crypto.randomUUID(); await s.put("salt", salt); }

// 接続元の IP アドレス + 塩 → SHA-256 → 先頭の 16 文字だけ使う
const ip = request.headers.get("cf-connecting-ip") || "unknown";
const h = await hash(salt + ip);

async function hash(text) {
  const d = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(text));
  return [...new Uint8Array(d)].slice(0, 8).map(b => b.toString(16).padStart(2, "0")).join("");
}
```

ここからは、このコードでやっている「**塩付きハッシュ**」について、順番に説明します。

## ハッシュとは

ハッシュ（ここでは SHA-256 という計算方法）は、どんな長さの文字でも、**決まった長さのでたらめに見える文字** に変える計算です。次のような性質があります。

1. **同じ文字からは、いつも同じ結果になる**
2. **1 文字でも違えば、まったく違う結果になる**
3. **結果から、元の文字に戻すことはできない**（計算が一方通行）

たとえば、IP アドレスの最後の数字が 1 つ違うだけで、結果はまったく別物になります（どちらも説明用の IP アドレスです。このワールドでは、結果の先頭 16 文字だけを使っています）。

| 元の文字 | SHA-256 の結果（先頭 16 文字） |
|---|---|
| `203.0.113.45` | `eb4b2dd34d5ba9af` |
| `203.0.113.46` | `679c14e80e44a670` |

性質 1 のおかげで、「**同じ IP アドレスから来た記録かどうか**」は、ハッシュ同士を比べるだけで分かります。性質 3 のおかげで、ハッシュを見ても IP アドレスは分かりません。

## ハッシュだけでは足りない理由

「戻せないなら、ハッシュにするだけで十分では？」と思うかもしれません。ところが、IP アドレス（IPv4）は全部で **約 43 億通り** しかありません。43 億回の計算は、今のパソコンなら数分から数十分で終わってしまいます。

つまり、ハッシュ `eb4b2dd34d5ba9af` を手に入れた人が、

> 「0.0.0.0 から 255.255.255.255 まで全部ハッシュにして、`eb4b2dd34d5ba9af` になるものを探そう」

とすれば、元の IP アドレスが見つかってしまいます（これを **総当たり** といいます）。「戻す」のではなく「全部試して当てる」やり方です。

## 塩（ソルト）とは

そこで、ハッシュにする前に、**サーバーだけが知っているランダムな文字列（塩）を IP アドレスにくっつけます**。料理で、秘密の調味料をひとつまみ混ぜるイメージです。

| 元の文字 | SHA-256 の結果（先頭 16 文字） |
|---|---|
| `203.0.113.45` | `eb4b2dd34d5ba9af` |
| `salt-example-7f3a` + `203.0.113.45` | `175fa93aaae80674` |

（`salt-example-7f3a` は説明用の塩です。本物の塩は、もっと長いランダムな文字列です）

塩を混ぜると、同じ IP アドレスでも結果がまったく変わります。総当たりをしようとしても、**塩を知らないと「何をくっつけて計算すればいいか」が分からない** ので、43 億通りを全部試しても同じ結果を作れません。

- 塩は、サーバーが最初に `crypto.randomUUID()` で 1 回だけ作ったランダムな文字列で、**サーバーの中にだけ** 保存しています（コードにも Gist にも書いていません）。
- 同じ人（同じ IP アドレス）からの記録は、毎回同じ塩を使うので **毎回同じハッシュ** になります。だから「同じ人の記録をまとめる」ことはできます。
- 塩が分からない外の人には、ハッシュから IP アドレスを当てる方法がありません。

まとめると、塩付きハッシュは「**同じ人かどうかは分かるけれど、その人の IP アドレスは分からない**」状態を作るための仕組みです。

サーバーが覚えているのは、このハッシュと、点数・称号の組み合わせだけです。

```js
// 覚えている記録（上位 50 件だけ）
{ h: "a3f09c1e7b2d4458", s: 150, d: "2026-11-08", c: "JP" }

// 選んだ称号（ハッシュごとに番号を 1 つ。最大 500 人分）
{ "a3f09c1e7b2d4458": 3 }
```

| 項目 | 中身 |
|---|---|
| `h` | 接続元の塩付きハッシュ（IP アドレスには戻せない） |
| `s` | 点数 |
| `d` | その点数を出した日付 |
| `c` | 国コード（下で説明） |
| 称号 | ハッシュごとに、選んだ称号の番号（称号は記録とは別に送るので、同じハッシュで記録と結び付けている） |

同じハッシュから新しい記録が来たら、**行を増やさずに点数だけ上書き** します。これで、同じ人の記録が何個も並ばなくなります。

# 国の表示について

ランキングには国名（「日本」など）が出ます。これは、サーバーを動かしている **Cloudflare が、接続元から判断した国コード（`JP` など）** をそのまま使っています。

```js
const c = (request.cf && request.cf.country) ? String(request.cf.country).slice(0, 2) : "";
```

- 分かるのは **国だけ** です。都道府県や市区町村のような細かい場所は、保存も表示もしていません。　（実は自分はよく「何県に住んでいるのですか」と聞かれたときに、嘘をつくことがあったりするので、それがばれたらやだなーと思ったからです。ただ理論上は都道府県をわかることもできます）
- VPN を使っている人は、その VPN の国になります。

# 公開されるデータ

ワールドが読む Gist（誰でも見られます）には、**上位 5 件の次の情報だけ** が書かれます。

```json
{"top":[{"s":150,"d":"2026-11-08","c":"JP","b":3}]}
```

- 点数・日付・国コード・称号の番号だけです。**ハッシュも書き出していません。**
- ワールドの中で名前が出るのは、「**今同じインスタンスにいる人** の最高点と、ランキングの点数が同じとき」だけです。これはワールドの中だけで計算していて、名前をサーバーに送ってはいません。

# 荒らし対策

ハッシュを使って、同じ接続元からの送信を制限しています。

- 10 秒に 1 回まで
- 1 日 100 回まで
- 点数は 0〜3000 点まで（ワールドで出せない点数は受け付けない）

この回数を数える表も、サーバーのメモリの中にだけあり、日付が変わると消えます。

# できないこと・気をつけてほしいこと

正直に書いておきます。

- **送った記録は、あとから取り消せません。** ワールドのスイッチはいつでもオフにできますが、オフにすると「これから先は送らない」になります。
- **ハッシュを作れるのはサーバーの中だけ** です。サーバーの持ち主（私）は塩を持っているので、理屈の上では総当たりで IP アドレスを探すことができてしまいます。自分はそれをしません（知ったところで使い道もないので…）。そのための仕組みも作っていません。ただ、「数学的に誰にも戻せない」わけではない、という点はお伝えしておきます。
- サーバーは Cloudflare の上で動いているので、通信そのものは Cloudflare を通ります（普通の Web サイトを見るときと同じです）。
- 同じ家や同じネットワークの人は IP アドレスが同じことがあるので、**同じ人として 1 行にまとまる** ことがあります。

# まとめ

| | 送る | 保存する | 公開する |
|---|---|---|---|
| 名前（表示名） | ✕ | ✕ | ✕（同じインスタンスの人にだけ、ワールドの中で表示） |
| IP アドレス | （通信なので届く） | ✕（塩付きハッシュだけ） | ✕ |
| 点数・日付 | ○ | ○ | ○ |
| 国 | （Cloudflare が判断） | ○ | ○ |
| 称号 | ○ | ○ | ○ |

「同じ人の記録をまとめる」「荒らしを防ぐ」ためにだけ、IP アドレスを元に戻せない形にして使っています。不安なときは、スイッチをオフのままにしておけば何も送られません。
